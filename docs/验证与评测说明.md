## 检索评测

`evaluation/datasets/project_baseline.jsonl` 仅包含公开项目知识和不可回答问题，不包含私人简历事实。先将项目文档导入并完成向量索引，再运行：

```bash
cd backend
python scripts/evaluate_retrieval.py \
  --dataset evaluation/datasets/project_baseline.jsonl \
  --user-id ADMIN_USER_ID \
  --knowledge-base-id KNOWLEDGE_BASE_ID
```

报告包含 Recall@K、可回答命中率和不可回答召回率。单元测试中的 100% 是 Fake Retriever 的框架自测，不是实际模型成绩，不能用于简历或上线结论。

为避免手工导入遗漏，可在空的隔离 PostgreSQL/pgvector 数据库中使用公开项目快照一键构建语料、调用真实 Embedding 并评测多个 K：

```bash
cd backend
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:55432/knowledge_agent \
python scripts/run_project_baseline.py --top-k 1 4 10
```

该脚本仅导入当前仓库经 Git 清洗后的公开文档，不读取私人简历；它会输出导入文件数、Chunk 数和每个 K 的 `recall_at_k`、`answerable_hit_rate`、`unanswerable_recall`。在 Windows PowerShell 中请先用 `$env:DATABASE_URL='...'` 设置临时环境变量。

2026-09-14 的首次复测曾因 GitHub Models Embedding 返回 `410 github_models_retirement_brownout` 而阻断。现已迁移至本地 FastAPI/FlagEmbedding BGE-M3 主服务，并完成一次真实基线评测。评测使用 Git 清洗后的公开工作区快照（96 个文件、19 个 Chunk）与 12 条固定样本；这不是 Fake Retriever 成绩，也不是生产 SLA。

```json
{
  "top_k_reports": {
    "1": {"recall_at_k": 0.3333, "answerable_hit_rate": 0.4, "unanswerable_recall": 0.0},
    "4": {"recall_at_k": 0.6667, "answerable_hit_rate": 0.8, "unanswerable_recall": 0.0},
    "10": {"recall_at_k": 0.6667, "answerable_hit_rate": 0.8, "unanswerable_recall": 0.0}
  }
}
```

指标定义如下：

| 指标 | 计算 | 当前判定 |
| --- | --- | --- |
| Recall@K | 每条可回答题的 Top K 合并文本同时包含其全部 `expected_terms` 的比例 | K=1：33.3%；K=4：66.7%；K=10：66.7% |
| 可回答命中率 | 与 Recall@K 相同，单独查看可回答子集 | K=1：40.0%；K=4：80.0%；K=10：80.0% |
| 不可回答召回率/拒答命中率 | 不可回答题返回空检索结果的比例 | K=1/4/10 均为 0%；符合当前未设相似度阈值的预期 |
| 端到端拒答正确率 | 不可回答题中最终响应为固定拒答、且模型未被调用的比例 | 当前未有端到端真实集；现有单元用例只验证控制流 |

当前实现没有相似度拒答阈值，未知问题若仍检索到低分 Chunk，检索层不会返回空结果。因此即使恢复 Embedding 服务，也应预期不可回答召回率可能偏低；该结果将作为引入阈值前的基线，而不是被掩盖。

### 当前 RAG 参数与拒答边界

本项目当前没有通过离线评测选出的“最优 Token 参数”，以下是已实现、可从代码复核的运行值，不能表述为效果调优结论。

| 项目 | 当前实现 | 说明 |
| --- | --- | --- |
| Chunk 大小 | 2400 字符 | `chunk_pages` 优先按段落聚合；超长段落再按窗口切分。`token_count` 是 `字符数 / 4` 的近似记录，不是模型 tokenizer 的精确 Token 数。 |
| Chunk 重叠 | 300 字符 | 约为窗口的 12.5%，只在相邻 Chunk 之间保留尾部文本。 |
| 问答 Top K | 4 | 会话服务调用检索时固定 `limit=4`，最多将 4 条证据写入上下文。 |
| 通用检索默认 Top K | 10 | `RetrievalService.search` 的默认值；离线脚本的 `--top-k` 默认也是 10，可显式改写用于对比。向量查询每个扩展 Query 先取 `max(3K, 12)` 个候选，再做来源均衡。 |
| 拒答阈值 | 未配置数值阈值 | 当前仅在“检索结果为空”时确定性拒答；没有相似度分数 cut-off。低分但非空结果仍会进入 Prompt，因此分数阈值是待评测后实现的优化项。 |

### 本地 Embedding 迁移（FastAPI + FlagEmbedding/BGE-M3，Ollama 回退）

2026-09-14 已将主路径适配为独立 FastAPI 服务：Docker Compose 的 `embedding` 服务使用 `BAAI/bge-m3`/FlagEmbedding，暴露 OpenAI 兼容的 `http://embedding:8001/v1/embeddings`。模型使用 1024 维输出。Ollama `bge-m3` 保留为开发或服务故障回退。迁移 `20260914_01` 会清空旧向量、将来源版本标记为待索引；这是必要操作，因为不同模型或实现生成的向量不能混合检索。

```bash
# Compose 会构建 FastAPI/FlagEmbedding 服务并在首次启动下载模型
cd deploy
docker compose up --build

# 项目：执行数据库迁移并重建已有 Chunk 向量
cd backend
alembic upgrade head
python scripts/reindex_embeddings.py
python scripts/run_project_baseline.py --top-k 1 4 10
```

主路径以 OpenAI 兼容接口返回 BGE-M3 的 1024 维、L2 归一化 dense 向量；它不需要第三方 API Key。实际验证确认该接口可返回 2 条、各 1024 维向量；后端对该本地端点使用 `EMBEDDING_BATCH_SIZE=4` 与 `EMBEDDING_REQUEST_TIMEOUT_SECONDS=300`，避免把云端默认批量/超时误用于 CPU 推理。Ollama 回退已在宿主机真实返回 1 条 1024 维向量；若需从 Compose 容器访问它，Ollama 必须额外监听非回环地址，`host.docker.internal:11434` 才可连通。

模型首次下载的端点由 `HF_ENDPOINT` 控制，Compose 默认使用 `https://hf-mirror.com`；在可直接访问 Hugging Face 的环境可显式设置为 `https://huggingface.co`。若两者都不可达，应先处理服务器出网或通过离线方式预置模型缓存，而不是反复重启容器。

服务会先以 `snapshot_download` 下载推理所需模型文件，并忽略仓库中的示例图片目录 `imgs/*`；这样可避免镜像站拒绝非推理资源（例如 `.DS_Store`）时阻断整个模型启动。

Compose 同时设置 `HF_HUB_DISABLE_XET=1`，避免受限网络通过 Hugging Face Xet/CAS 通道下载权重时出现 401；模型权重会回退为普通 HTTP 下载。

### 访客问答耗时的测量口径

“首批文字约 1.24 秒、总耗时约 2.78 秒”仅可作为一次成功链路的体验采样，不能称为 P50/P95、压测数据或生产 SLA。测量时保持同一浏览器、网络、模型、知识库、问题和冷/热状态，并至少重复 10 次后分别报告中位数和 P95。

- 起点 `t0`：浏览器发起 `POST /api/v1/conversations/{id}/messages:stream` 的时刻（Network 面板请求开始）。
- 首字/首批文字 `TTFT`：收到首个非空 `event: delta` 的时刻减 `t0`；不把 `metadata`、`citation` 等非回答事件算作首字。
- 总耗时：收到 `event: done` 的时刻减 `t0`；若收到 `event: error`，单独记录失败，不混入成功样本。
- 同时保存请求时间、问题 ID、返回字数、是否命中拒答、模型、知识库版本与原始 SSE 时间戳，以便复跑和排除缓存/网络波动。
